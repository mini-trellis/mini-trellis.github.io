# 怎么工作

会话开始时注入一段短入口，大约 1.1k 字符。后面的轮次不再注入。改动依赖以前的决定时再查。这次会话得出一条以后还要用的规则或修复时，写进已有笔记，并记一笔会话。

## 四个地方

一个支付服务里，重复回调造成了重复扣款。修好之后，规则留在仓库里。

| 内容 | 位置 | 例子 | 下次什么时候用 |
| --- | --- | --- | --- |
| 约定 | `.trellis/spec/` | 每个回调带幂等键。先读 `index.md`。 | 要改回调处理或它的契约。 |
| 调研 | `.trellis/research/` | 重试上限、放弃过的做法、服务商文档。旧主题放到 `archive/`。 | 服务商改了 API，要看当初为什么这样定。 |
| 日志 | `.trellis/workspace/<你>/` | 重复扣款的原因、改过的文件、通过的测试。 | 又来一份类似的故障，要找回上次怎么查的。 |
| 对话 | Agent 本机日志 | 用 `mini-trellis mem` 查当时的讨论。 | 要分清哪个方案被否了，哪个是留下的决定。 |

## 什么时候写

普通改动直接写代码。不用先建任务，也不必每次聊天结束都跑 `remember`。

规则或以前的决定不在眼前时，跑 `mem recall`。摘录够了就停。不够再 `mem read "<ref>"`。只查对话用 `mem search` 和 `mem context <session-id>`。

以后的会话还需要这条结论时才记。已有同主题文件就改那个文件。要长期遵守的边界用 `mini-trellis-update-spec` 写进 `spec`。然后 `remember` 在日志里链到这次会话。新安装只写文件，不自动提交。

一次改动里的命令顺序见[日常使用](/zh/using/)。
