# v0.4.0 — Put confirmed knowledge to work

2026-11-16.

v0.4.0 focuses on an everyday loop: save a confirmed decision, use it in the next development session, revise the original topic when the decision changes, and update the documentation with the implementation.

## A continuous recording workflow

Confirmed decisions and corrections lead into topic updates, one content check, and journal recording. The current rule stays in one document with its conditions, negations, and original language. Future agreements carry their implementation status, and development changes update the affected descriptions.

## Reliable saves and retries

Recording runs sequentially within a checkout and checks the saved journal and index. If the journal is saved before the index is complete, repeating the command resumes the remaining work. Repairing an older entry preserves the counts for later records.

New topic-linked records include the topic's content version. A correction can therefore get its own record even when the title and summary stay the same. Existing journals, topic links, and legacy record recovery remain available. Test notes retain the supplied outcomes, with development status based on the work performed.

## The right project context

Recall, recording, and the shared startup entry resolve the nearest initialized project across subdirectories, nested projects, Git worktrees, and non-Git projects. Independent repositories use their own knowledge, and runtime records stay with the corresponding project.

## Start with one real rule

1. Save a confirmed rule in an existing README, guide, or knowledge topic.
2. Open a new session and request related development work so the agent can find and use it.
3. Update the same topic when the decision changes, then use the revised rule in the next change.

See [Day-to-day use](/using/) and [Writing notes](/writing-notes/).

## Upgrade

From 0.3.8, run in your project root:

```bash
mini-trellis upgrade --tag 0.4.0
mini-trellis doctor
```

For direct npm installation or updates, refresh the project afterward:

```bash
npm install -g mini-trellis@0.4.0
mini-trellis refresh
mini-trellis doctor
```

Refresh each project you use, then open a new agent session. Existing knowledge and explicit configuration are preserved. See [Upgrade](/upgrade/).
